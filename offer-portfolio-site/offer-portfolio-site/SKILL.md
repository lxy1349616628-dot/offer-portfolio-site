# 求职作品集网站

产出一个 `index.html`：双击就能打开，也能直接拖到任何静态托管上线。页面结构固定：

1. **首屏**：照片、名字、求职方向、一句话简介、三个关键数字
2. **能力版图**：细胞图，中间是核心能力（细胞核），周围最多四个能力（细胞器），点一下展开详情
3. **作品分区**：每个作品一张卡片，含图片（原比例展示，可左右滑）、简介、数字、按钮，底部是“你可能想问”的追问，点开有回答
4. **视频样片**：竖版封面横向滑动，可跳转到视频链接
5. **联系**：联系方式、简历下载

模板在 `assets/template.html`，内容全部来自一个 `data.json`，示例见 `assets/example-data.json`。不要改模板去塞内容，只写 data.json。

## 流程

### 1. 读材料

用户需要提供：简历（必需）、作品集、一张个人照片、作品截图、视频封面（可选）、简历PDF（可选）。全部读完再开口，别问材料里已经写了的东西。

### 2. 优化简历

用户上传的简历往往不够完善，先按 `references/resume-guide.md` 做一遍：诊断写得虚的地方，追问缺的真实信息，按目标岗位出一版优化稿（`resume-optimized.md`）。网站后面所有的文案和数字都从这版优化稿里取。

用户明确说不需要改简历时，跳过这一步，但仍然检查简历里的数字和作品名有没有前后矛盾。

### 3. 一次问清网站需要的信息

简历优化时已经问过的不再问。一条消息问完，最多六个问题：

- 网站上显示什么名字（真名、英文名或昵称）
- 求职方向，2—3个岗位
- 愿意公开哪些联系方式（提醒：公开网页不建议放手机号）
- 哪些作品要放、哪些不放
- 截图里有没有要打码的名字、ID、作品名
- 配色偏好；没有偏好就从照片里取色

### 4. 先给骨架，再写文案

列出：三个首屏数字、能力版图的五个能力、每个分区放哪些作品。用户确认后再写完整文案。

### 5. 写 data.json

照 `assets/example-data.json` 的结构写，放在工作目录，图片放在旁边的 `images/` 里，路径写相对路径。字段说明见下方速查。

### 6. 生成

```bash
python3 scripts/build.py work/data.json -o work/index.html
```

脚本会把图片压缩后内嵌进HTML，输出单个文件，并提示缺失的图片。没装 Pillow 时先 `pip install pillow`（装不上也能跑，只是不压缩）。

### 7. 交付

把 `resume-optimized.md` 和 `index.html` 一起发给用户，一两句说明：

- 双击即可在浏览器打开，手机上看效果最好，录屏建议用 Chrome
- 想要一个能分享的链接：拖到 Netlify Drop（app.netlify.com/drop）就能拿到网址，也可以用 GitHub Pages、Vercel
- 以后改字：直接告诉你改哪里，改 data.json 后重新生成

如果当前环境能发布网页（例如有 Artifact 工具），也可以直接发布成链接。

### 8. 修改

用户常会截图圈出要改的地方。逐条改 data.json，再重新生成。改动涉及事实或数字时，优化稿里对应的地方也一起改。改完简要列出改了什么，自己做了判断的地方单独说明，让用户确认。

## 文案规则

这些规则来自真实使用中被反复要求修改的地方，务必遵守：

- **只用材料里的事实。** 缺的数字、做法、原因不要编，写成 `[待补充：xxx]`，交付时列出来。
- **同一个数据全站一致。** 截图和简历数字不一致时，以截图为准，首屏、作品卡、追问、视频说明一起改。
- **首屏简介写成简历腔的一句话**：学校专业＋经验年限＋身份。不写口号、不写“热爱”“擅长”之类的空话。
- **首屏数字**挑最能打的三个，标签写清口径，例如“互动文游宣传单条播放”，不要只写“播放量”。
- **能力版图按简历“专业技能”栏的写法**：一句话说会什么、用什么工具，再配一个简单结果作为标签（`result`）。不要空泛的自我评价，不要分条列点，也不要和作品区逐字重复。
  - 核心能力默认是 AI 能力，四个小格：产品设计、用户思维、效率提升、流程复用（把重复工作沉淀为可复用的工作流）。用户没有 AI 经历时，把核心换成他最强的能力。
  - 核心能力的 `summary` 控制在 30 字以内，四个小格每格 25 字以内，否则展开面板放不下。
  - 不要在文案里出现“细胞核”“细胞器”这类比喻词，那只是视觉形式。
- **作品卡**：`kicker` 写类型或时间，`desc` 一两句，数字最多三个，追问一到两条。
- **追问要像 HR 真会问的**，常用三类：“你在这个产品中发挥了什么作用？”（用了 AI 的作品必须说清人和 AI 的分工）、“设计思路”、“××是怎么做到的？”。回答用第一人称，两三句。
- **少用排比、少用形容词**，一句话能说清就不拆成列表。
- **隐私**：不放手机号、证件号；截图里别人的名字、ID、头像要打码；含成人内容的作品不放全文，最多放标题和节选入口。

## 图片

- 作品图按原比例完整显示，不裁切，所以截图不用预先裁剪。
- 视频封面最好是竖版（9:16）；比例差很多的封面加 `"fit": "contain"`，避免把字切掉。
- 一个作品可以放多张图，会变成可左右滑动的图集，数据截图可以放在作品图后面。
- 打码用马赛克，坐标按原图尺寸算，打完裁一块出来看一眼再用：

```python
from PIL import Image
im = Image.open(src).convert('RGB')
def mosaic(box, cell=22):
    r = im.crop(box); w, h = r.size
    r = r.resize((max(1, w // cell), max(1, h // cell)), Image.BILINEAR).resize((w, h), Image.NEAREST)
    im.paste(r, box)
mosaic((x1, y1, x2, y2))
im.save(dst, quality=88)
```

## data.json 速查

| 字段 | 说明 |
|---|---|
| `meta.title` | 浏览器标签页标题 |
| `theme` | `ground` 底色、`ink` 文字色、`accent` 强调色、`soft` 浅强调底色、`muted` 次要文字色，可只写部分 |
| `profile` | `name`、`roles`（数组，每项一行）、`intro`、`photo`、`year` |
| `stats` | 首屏三个数字 `{num, label}` |
| `abilities.core` | `label`、`en`、`summary`、`subs`（最多4个 `{name, desc}`） |
| `abilities.items` | 最多4个 `{label, en, summary, result}`，可选 `color` |
| `sections[]` | `title`、`nav`（导航上的两个字）、`type`：`works` 或 `videos`、`intro` |
| `works[]` | `kicker`、`tag`、`title`、`desc`、`images`、`stats`、`cta {label, link}`、`qa [{q, a}]` |
| `videos[]` | `title`、`meta`、`cover`、`link`、`fit`、`pos` |
| `contact` | `headline`、`text`、`rows [{label, value, link}]`、`resume {label, file}` |
| `qaTitle` | 追问区的标题，默认“你可能想问” |

**配色**：默认是深棕、玫瑰红、浅粉底。从照片取色时，`ink` 取画面里最深的主色，`accent` 取最鲜明的颜色，`soft` 是 accent 的极浅版本。强调色放在底色上要看得清（对比度至少 4.5:1），不确定就加深一档。
